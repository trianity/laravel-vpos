This document is the Prompt 01 evidence snapshot. It describes the repository at the start of the step and does not claim sandbox verification. Runtime package behavior was not changed in this step.

### Test inventory and execution boundary

The current suite is entirely deterministic and calls `Http::preventStrayRequests()`. Synthetic merchant/gateway key pairs and `gateway.test` fakes cover canonicalization, transport, hosted-card lifecycle, all wallet operations and Laravel entry points. The abandoned live sandbox tests, hard-coded paths, raw cURL client and placeholder compatibility tests were deleted rather than skipped.

## Status vocabulary

- **Offline verified**: deterministic local evidence exists and no bank request is possible.
- **Sandbox verified**: an authorized run reached the pinned K&H sandbox and retained sanitized evidence.
- **Awaiting merchant setup**: implementation exists, but credentials, entitlement, test card, wallet account or device are required.
- **Confirmed exclusion**: pinned upstream evidence establishes that the operation is outside the supported surface.
- **Unresolved gap**: neither adequate implementation evidence nor a justified exclusion exists.

The authoritative Prompt 07 row-by-row closure, including exact test names and current sandbox status, is in [Acceptance evidence and sandbox runbook](acceptance-and-sandbox.md#closure-of-the-17-php-sample-operations). Every one of the 17 sample operations is offline verified; GET and POST Echo are additionally sandbox verified.

## Source conflicts and decisions

1. **Hosted process status:** Basic Methods and Java require HTTP 303. A generic 2xx success check is wrong. The browser owns the redirect.
2. **Raw JSON vs wrapped body:** PHP Guzzle uses `body => json_encode($request)`, .NET uses serialized DTO `StringContent`, and Java sends the DTO entity. Prompt 03 corrected package POST/PUT calls to top-level JSON; operation-specific wire assertions remain with their lifecycle prompts.
3. **Close amount name:** Basic Methods and the supplied PHP DTO use `totalAmount`; the Hungarian partial-payment prose says `amount`. Use `totalAmount` for `payment/close`, reserving `amount` for refund, pending sandbox confirmation only if a merchant-specific document disagrees.
4. **Google Pay signing order:** the wiki request table places `payload` before return/customer/order and `merchantData` later. `WalletSchema` follows the wiki/Java/.NET wire model.
5. **Booleans:** canonical text uses lowercase `true`/`false`; integer `1` is not accepted as wire-equivalent.
6. **`echo/customer`:** treat the README line as stale because no executable PHP mode exists and the pinned official changelog removes the operation.

### Consumers and parallel implementations

- `PaymentController` resolves the shared verified `Vpos` singleton and a host-bound `CheckoutDataProvider`. It accepts only an order reference, uses server-owned amount/cart/context, reads the HTTPS return URL from configuration, verifies Echo/init responses and returns a Laravel redirect to the signed handoff URL.
- `tests/PackageTestCase.php` boots without `LaravelDataServiceProvider` and prevents every stray HTTP request.
- The `Services` client tree, `ApiService`, duplicate crypto wrappers, raw cURL client and placeholder facade method do not ship.
- `Facades\KHVpos`, `khvpos` and `Vpos::class` resolve the same lazy singleton. It exposes verified Echo/init/process URL/status/browser-return and wallet boundaries.

## Deterministic fixture provenance and rules

- `tests/Fixtures/merchant-*` and `gateway-*` are two unrelated, synthetic RSA-2048 key pairs generated solely for this repository with OpenSSL. They are not K&H or merchant credentials.
- Fixed timestamps are `20220125131559` (request) and `20220125133016` (response), copied from the pinned signing/basic-method examples.
- `PAYMENT_INIT_CANONICAL` is copied verbatim from the pinned official signing example. It is not produced from the implementation under test. The test signs it with the synthetic merchant private key and verifies it with the independently stored public key.
- Echo response canonical text is independently assembled as `20220125133016|0|OK` from the Basic Methods response field order and signed with the synthetic gateway private key.
- Default Laravel coverage calls `Http::preventStrayRequests()` and only uses `gateway.test` fakes. No raw cURL path exists.
- No production/sandbox key, PAN, token, live URL payload, or bank response is stored in fixtures.
