# Prompt 01 — Establish the baseline and parity matrix

Work in `trianity/vpos`. Read the shared rules and pinned sources in [docs/README.md](README.md). This task prepares evidence and test infrastructure. Keep runtime behavior unchanged in this step.

1. Record the branch and SHA, PHP and Composer versions, actual locked framework/Testbench/Pest/PHPUnit versions and PHP constraints. Run `composer validate --strict` and attempt an install from the existing lock in a compatible environment. Report version or environment blockers separately. In particular, distinguish the package's PHP `^8.4` consumer claim from the PHP requirement of its locked development tools. Inventory all tests, identify real HTTP/key dependencies and unconditional skips, and record what actually ran.
2. Add `docs/eapi-v1-parity.md` with one row for each of the 17 sample operations. Include method/path, redirect semantics, required and conditional fields, response and error shape, signing source, package entry point, current gap, test evidence and status. Track standard and OneClick-template init separately under the same endpoint. Add separate rows for browser return verification, documented extensions, and optional specification-only features. Record the `echo/customer` exclusion. Flag sample/spec conflicts with references, including where Java or .NET examples clarify the wire format.
3. Inventory Spatie-backed DTOs and consumers across `src/Services`, `src/DataTransferObjects/EuVatData.php`, `Helpers`, the controller, and `tests/PackageTestCase.php`. Inventory both API services, both crypto services and the facade. Identify which DTO surface is public, including constructor defaults, writable versus readonly fields, factories, `all()` versus `toArray()`, enum conversion, nullable fields and nested hydration.
4. Set up deterministic fixtures and test helpers for subsequent steps. Derive expected canonical strings from the spec or a cross-checked reference, never the code under test. Use two synthetic RSA key pairs, fixed timestamps, no actual bank access, and `Http::preventStrayRequests()` for Laravel HTTP coverage. Handle any cURL path explicitly because Laravel fakes do not intercept it. Replace accidental live calls in default tests with meaningful offline equivalents or move demonstrably live scenarios into a clearly opt-in test group.

Acceptance criteria: every sample operation is accounted for, the offline baseline is reproducible or has an explicit blocker, fixture provenance is recorded, and no failed or skipped test is reported as verified.
